# cumm — build notes
- **Source:** FindDefinition/cumm (v0.7.11, commit b8d83b65). 0.7.11 and not
  0.8.x because spconv 2.3.8's harness cannot compile 0.8.x's GEMM headers
  (farm revert of 2026-08-22); upstream spconv pins `cumm<0.8`.
- **Build:** pccm/ccimport, driven by upstream's `setup.py` with
  `CUMM_DISABLE_JIT=1`. ninja through ccimport; **zero nvcc translation
  units** — core_cc is 39 C++ files against the CUDA runtime, so on linux-64
  the compile ledger comes from `.ninja_log` (build.sh's ninja-ledger
  fallback) rather than the nvcc seat.
- **Torch-free** (`links_torch: false`): one build per (cuda, python). No
  torch at build, compile or link time.
- **Runtime kernels are NVRTC-compiled.** core_cc ships no device code
  (`verify.no_sass`); the GEMM/conv kernels are generated by pccm and
  compiled through libnvrtc at run time. That path needs the CUDA headers on
  the machine (cumm 0.7.11 locates them through `nvcc` on PATH or
  `/usr/local/cuda`) — a property of the upstream, recorded in package.yml
  beside the run deps.
- **Patch (`patches/cumm.py`):** Blackwell/Thor in the arch table, bf16 GEMM
  params, the zero_whole_storage_ binding, the include-path sentinel, NVRTC
  std shims, an inline demangler, and — new here — no explicit link of
  `libnvrtc-builtins`, whose exact-minor soname would bind the `.conda` to
  one CUDA minor. The wheel carries the builtins through
  `wheel_vendor_extra` instead.

## Overrides

- **`arch_override.yml`** — overrides the shared arch policy's lists per CUDA
  line (`arch_list_by_cuda`), ported from cuda-wheels. See the file's own
  comment: the tokens have to parse in cumm's table, and the table is the
  one spconv reads too.
