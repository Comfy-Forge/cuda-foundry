# natten — build notes

- **Source:** SHI-Labs/NATTEN v0.21.6 (`4472b95f`), recursive
  (third_party/cutlass).
- **Build system:** setup.py drives cmake (Makefiles on Linux, Ninja on
  Windows). ~144 CUTLASS kernel instantiations are generated by
  `scripts/autogen_*.py` inside `build_ext`, plus 14 hand-written dispatch
  TUs in `csrc/src/*.cu` and `csrc/natten.cpp`; one module, `natten.libnatten`.
- **Torch floor:** setup.py asserts torch >= 2.5.

## Overrides

- **`arch_override.yml`** — NATTEN's documented floor is sm_80, so the shared
  row's 7.0/7.5 are dropped. Hopper (9.0) and Blackwell DC (10.0) enable
  their own kernel families and are built as sm_90a / sm_100a in separate
  object libraries; 12.0 carries the PTX tail. win-64 has its own rows
  (`arch_list_by_cuda_win`, read by generate_matrix.py) without 10.0: MSVC
  rejects NATTEN's sm_100 FNA backward kernel header with C2061 (run
  34587897208, 22 of 23 shards, at this revision and toolset).

## Sharding: the package partitions itself

`sharding: 23` with `shard_partition: source`. The translation units do not
exist until autogen runs inside the build, so no `shard_sources` glob can
name them; the patched setup.py deletes every `.cu` outside its round-robin
slice when `CUW_SHARD_COUNT > 0`, on both platforms. Linux keeps the nvcc
seat wrapper as a pure ccache pass-through (running its hash partition as
well would compile the intersection); win-64 caches through cmake's
`CMAKE_CUDA_COMPILER_LAUNCHER` instead of torch's `PYTORCH_NVCC`, and its
shard gate requires every nvcc TU ninja built to have been stored. 23 is the
farm's structural ceiling: the Hopper family has ~22 members and gets 0 or 1
per shard.

`natten.cpp` (the pybind module) is compiled uncached in every shard on
both platforms, as flash-attn's `flash_api.cpp` is: nothing caches the host
compiler's TUs, and the link job compiles it for real once.

## Patch

`patches/natten.py` — the farm's patch re-read against v0.21.6: pyproject
name/where fixes, the per-arch OBJECT libraries, MSVC/nvcc noise
suppression, `$ORIGIN` RPATH, the `not` token in helpers.h, the env-var shim
(TORCH_CUDA_ARCH_LIST with +PTX, MAX_JOBS, a pinned in-tree build dir), the
+PTX-aware cmake tags, the shard partition, and `-DCXX_STD` chosen at build
time from the torch built against (the farm decided it at patch time from
an env var this repo's fetch step does not have). Its configure-skip and
Windows /FORCE:UNRESOLVED blocks are not carried; neither applies here.
